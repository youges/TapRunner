# TapRunner 使用说明

适用版本：0.6.0。0.5.1 为首个公开发布版本。支持 Android 11–16。

TapRunner 用于在你自己的手机上执行重复点击、长按、直线滑动和简单自动化步骤。没有广告，不申请互联网权限，脚本、图像模板与日志保存在本机。

## 下载与安装

从仓库的 **Releases** 页面下载 `taprunner-0.6.0-release.apk`。GitHub 的 Source code 压缩包是源码，不能直接安装。

首次安装时，根据 Android 的提示允许当前文件管理器或浏览器安装应用。安装后打开 TapRunner，在「设置」中完成运行准备。请保留你下载的 APK，并核对发布页提供的 SHA-256。

已有正式版可使用同一发布签名覆盖更新，通常会保留脚本。更新前先保存或作废悬浮编辑器里的未保存点位，并建议导出重要脚本。更新会停止运行并重启应用。

开发调试版与正式版的签名不同，不能直接相互覆盖。若手机上安装的是开发调试版，先导出脚本，再卸载调试版、安装正式版并导入；卸载会清除本机应用数据。

## 先完成运行准备

在底部「设置」页查看各项状态。所有系统权限都由你自己开启。

| 项目 | 何时需要 | 操作 |
| --- | --- | --- |
| 坐标连点 | 普通点击、长按与滑动 | 开启「TapRunner 坐标连点」无障碍服务 |
| 高级识别 | 控件定位、等待文字/图像、文字输入、前台应用校验与音量键急停 | 按需开启「TapRunner 高级识别」 |
| 悬浮窗 | 在其他应用上设置点位和控制运行 | 允许 TapRunner 显示悬浮窗 |
| 通知 | 查看状态、从通知停止运行 | 允许通知 |
| 后台与电池 | 避免厂商后台管理中断运行 | 根据需要在系统电池优化、自启动、后台耗电管理中调整 |

普通坐标连点不读取页面内容。高级识别是可选服务。首页的「无障碍 · 已连接」表示服务已实际连接；系统开关开启后，如果仍显示等待连接，可以返回系统设置检查对应服务并重新开启。

部分系统会对侧载应用显示「受限制设置」。如果你信任自己下载的版本，可在系统应用信息中按系统提示允许。vivo 等厂商的后台设置入口会随系统版本变化；请按手机当前提示操作。

## 第一次多点连点

1. 首页选择「多点连点」，切换到目标应用的起始页面。
2. 悬浮栏点 **＋**。依次点击目标按钮；每次点击都会创建点位并操作页面。进入新页面后，等页面加载完成，再点下一个目标。按住可录入长按，划动可录入直线滑动。
3. 应用自动记录两次动作开始之间的时间，因此等页面加载的时间也会保留。不要连续快速点击还没加载出来的位置。
4. 点「完成并保存」。**先回到录入时的起始页面**，再点 **▶** 回放。新建多点脚本默认只执行一轮；要重复请在运行设置中调整轮数，并确保最后一步回到下一轮的起始页面。
5. 点位编号可以拖动调整；点击编号修改间隔。录入控制框标题可以拖动，避免挡住目标。录入中「撤销上一点」会撤销新增动作和它对脚本间隔的修改，但不会撤销目标应用已发生的操作。

录入会真实操作目标应用，点确认、发送、购买等按钮前请自行确认后果。需要只标位置时，使用悬浮栏「更多 → 仅标点（不操作页面）」。单点模式默认重复 100 次、最小间隔 200ms；多点默认一轮、最小间隔 500ms，录入时测得的单点间隔优先。

间隔表示本次动作开始到下一次动作开始的时间，包含按住和手势处理时间。超过 60 秒的录入等待会自动拆成间隔加等待步骤。手势依次派发，不会并行发送。

旧脚本不会自动修改。若旧脚本只有第一点有反应，检查第二步是否在页面加载前触发；建议重新录入，或增加前一步间隔，必要时使用等待文字/图像。系统报告手势完成并不保证目标应用接受了触点。

屏幕方向、分辨率、分屏和页面布局变化后，请重新确认点位。录入的是坐标和直线滑动起终点，不是完整曲线轨迹，也不会自动判断页面已加载。

## 暂停、继续与停止

悬浮控制栏和首页运行卡片提供暂停、继续、停止；通知也有「立即停止」。高级识别模式还支持长按音量下约 1.5 秒急停，纯坐标模式不监听音量键。

锁屏、息屏、旋转或运行期间无障碍失效会停止脚本。服务重新连接后不会自动续跑；先检查目标页面和点位，再手动开始。已发送给系统的一笔手势可能仍会完成，停止后不会继续派发新的手势。

## 管理脚本

底部「脚本」页可以按名称搜索，并按名称升序、名称降序或动作数排序。脚本卡片的「更多」菜单支持重命名、复制和删除。

- **重命名**：名称为 1～100 个字符。正在编辑这份脚本时，先保存或作废草稿。
- **复制**：复制已保存内容，生成新的脚本 ID；当前选择与未保存草稿保持不变。
- **删除**：弹出确认后才删除，确认前请先导出需要保留的内容。
- **加载点位**：将已保存脚本放到悬浮层中编辑和运行。

## 添加滑动与高级步骤

在「脚本」页进入「步骤编辑」，或在悬浮栏打开高级编辑器。悬浮编辑器默认采用紧凑尺寸，内容可以滚动；标题栏的「放大/缩小」可以切换尺寸，输入内容会保留。

选择「添加步骤」，再选择操作类型。点击、长按与滑动使用 0～1 的归一化坐标，例如 X=0.5、Y=0.5 表示屏幕中间。滑动需填写起点、终点和手势时长；当前滑动路径为直线。

可编辑点击、长按、滑动、等待、等待文字、有限循环、系统按键、输入文字、启动应用、日志与停止步骤。系统按键支持 `back`、`home`、`recents`。控件定位可使用文字、资源 ID 或描述；输入文字需要高级识别服务。

循环次数必须有限，子步骤通过步骤 ID 引用。条件分支、变量与失败策略目前仍需要在「高级脚本 JSON」中编辑；完整图形化条件编辑、曲线轨迹录制、批量间隔及完整撤销/重做尚未实现；基础录入支持撤销上一点。

图像等待使用本机截图模板。优先使用控件或文字等待；若页面不提供可访问控件，可以添加图像模板。目标应用禁止截图时会报错，不会绕过限制。

## 导入、导出与换机

「脚本」页提供导入入口，步骤编辑页提供导出功能。纯坐标/控件脚本可以导出 JSON；含图像模板的脚本应打包导出 ZIP，以便同时保留模板。

导入生成新的脚本 ID，不覆盖现有脚本。同名脚本可能同时出现，可以使用重命名整理。换机后导入并重新检查坐标与图像模板；目前没有自动迁移向导或导入冲突预览。

应用不依赖云同步，也不使用系统自动备份作为脚本迁移方式。请主动保存导出文件。

## 选择主题

首页右上角「外观」或底部「设置」进入外观页，支持 **跟随系统、白天、暗夜** 三种模式。配色提供靛蓝、青绿、紫罗兰、暖橙，也可以输入六位颜色值，例如 `#5367E8`。

选择会自动保存。暗夜模式会调整强调色的明度，并根据对比度选择按钮文字颜色。主题应用于主界面与悬浮控制；图标、点位编号使用各自的辨识颜色。手机的系统字体和字体大小仍会影响显示效果。

## 卡顿或运行不稳定时

先检查目标应用是否本身卡顿、是否存在遮挡弹窗，以及点击间隔是否过短。TapRunner 已减少主线程文件写入、重复窗口布局和频繁刷新，但系统手势派发、厂商电源管理和目标应用的处理速度仍会影响实际体验。

界面进度最多约每秒刷新 10 次，暂停、停止和故障会立即显示；这一限制不改变点击间隔或脚本执行频率。应用不会强制修改手机刷新率。

在「设置」进入「真机测试台」，可在应用自己的页面运行 100 次真实点击或 10 次往返滑动，以区分目标应用问题与 TapRunner 本身的问题。测试台会新增测试脚本；结束后可以保留，也可以通过脚本库确认删除。10,000 次测试耗时更长，请确保手机保持亮屏且可随时停止。

发生问题时，记录手机型号、Android 版本、应用版本、使用的服务、复现步骤和「运行日志」中的报错。分享日志前检查并移除你自己脚本中的私人内容。

## 当前验证与边界

0.6.0 的 98 项核心测试全部通过，debug/release 构建及 Android Lint 均通过，零错误、零警告。vivo X200s / Android 16 完成最终构建三步跨页回放、100 次点击全部接收和 10 次实际滑动。详细范围见 [验证记录](TESTING_0.6.0.md)。

尚未完成其他厂商的完整矩阵、10,000 次完整到达率和 8 小时连续运行测试。无障碍授权仍可能受厂商策略影响。OCR、Root/Shizuku、原始触摸轨迹录制等不在当前版本中。

仅用于你有权操作且符合目标应用规则的任务。
